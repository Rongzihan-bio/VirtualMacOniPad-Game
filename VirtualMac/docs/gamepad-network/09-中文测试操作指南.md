# iPad 手柄转发：中文测试操作指南

这是一份**开发测试**指南。当前方案会把 iPad 已连接的蓝牙或 USB
手柄，通过 UDP 发送到客体 macOS，再由客体的 root 权限 HID 接收器模拟
一个标准游戏手柄。

目前尚未实现认证，因此只应在自己的受信任网络中测试。

## 0. 测试前确认

- 客体 macOS 已按此前步骤关闭 SIP，且 `sudo guest-gamepad-probe` 可以
  正常显示 `active`。
- iPad 与虚拟机网络可互通。第一次端到端测试建议使用 **Bridge**，地址
  更直观；NAT 需要填写客体私有子网中的地址，不是网关地址。
- 已构建并安装含本次手柄代码的 Virtual Mac 测试包。安装包前请完全退出
  正在运行的 Virtual Mac。
- 手柄已在 iPad 的蓝牙设置中配对，或已通过 USB 连接。

## 1. 获取客体 macOS 的 IPv4 地址

在客体 macOS 的终端运行：

```sh
ifconfig en0 | awk '/inet / {print $2}'
```

记录输出，例如 `192.168.1.50`。若没有输出，先确认虚拟机网络已连接。

在 Bridge 模式下，通常应是局域网地址；在 NAT 模式下，通常是虚拟机专用
网段地址。不要填写路由器、iPad 或 NAT 网关的地址。

## 2. 在客体启动游戏手柄接收器

Steam/Wine 通用 IOHID 方案在客体 macOS 终端运行：

```sh
cd /path/to/VirtualMacOniPad
sudo VirtualMac/scripts/development/start-guest-gamepad-receiver.sh
```

正常开始监听时会显示：

```text
[gamepad-probe] listening on UDP 25863 (state timeout 750ms, ...)
[gamepad-probe] active: device=VirtualMac Network Gamepad feed:4790 (16-byte HID reports, until interrupted)
```

此窗口需要保持运行。按 `Control-C` 会停止并发送归零状态。

启动脚本固定创建通用 HID 手柄，供 Steam Input 手动映射以及 Wine/SDL
原始 IOHID 路径使用。它不依赖 Safari 或 macOS GameController.framework。
默认 750ms 断线归零可吸收短暂网络或 iPad 调度抖动；需要诊断实时状态时
在启动命令末尾添加 `--print-state`。每 10 秒打印的 `stats` 会报告序列跳号、
过期包、无效包和超时次数。

## 3. 在 iPad App 内配置和测试

1. 打开 Virtual Mac 的“设置”。
2. 进入“手柄网络转发与测试”。
3. 在“客体 IPv4”中填写第 1 步得到的地址，端口保持 `25863`。
4. 点击“保存并应用”。
5. 查看“实时输入”：按键、摇杆、扳机和方向键应随真实手柄变化。这里不依赖
   网络，可以先确认 iPadOS 是否正确识别蓝牙/USB 手柄。
6. 点击“发送测试状态”。若网络与客体接收器正常，“客体 ACK”会显示“正常”，
   Mac 终端也会打印当前按键和摇杆数值。
7. 单次测试通过后，再打开“启用手柄转发”开关，App 会以 60Hz 持续发送。

关闭页面不会停止已启用的转发；需要停用时关闭“启用手柄转发”开关。App 进入
后台或手柄断开时会先发送归零状态。

## 4. 验证

1. 启动 Virtual Mac，并保持客体第 2 步的接收器运行。
2. 按手柄 A/B/X/Y、方向键，移动左右摇杆并扣动扳机。
3. 在 Steam 的“控制器”设置中识别通用手柄，并完成按钮、摇杆、扳机和
   方向键映射；Wine/SDL 游戏也可直接读取通用 IOHID。
4. 关闭手柄或退出 Virtual Mac 后，接收器应在最多约 750ms 后显示：

   ```text
   [gamepad-probe] state timed out; neutralized
   ```

   这表示断线保护已归零，可避免游戏出现“按键卡住”。

### 丢包和长按诊断

接收器每 10 秒打印一行 `stats`：

- `received`/`accepted`：收到和接受的完整状态包；正常 60Hz 时每 10 秒约
  增加 600。
- `sequence-gaps`：序列跳号，代表 UDP 丢包。每包都是完整状态，少量跳号
  不需要重传。
- `stale`：重复或乱序包；`malformed`：格式错误包，正常应为 0。
- `timeouts`：连续 750ms 未收到有效包而自动归零的次数。长按意外松开时
  优先检查此值；必要时可用 `--timeout-ms 1200` 临时提高阈值。

接收器没有长按时长限制。只要 iPad 持续发送，同一按键会一直保持。批量
排空积压包时会保留所有按钮和方向键的按下/松开边沿，只合并重复的模拟量
中间状态。

## 5. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 接收器无法启动 | 确认使用 `sudo`；当前客体创建虚拟 HID 需要 root。 |
| GUI“实时输入”没有变化 | 手柄尚未被 iPadOS 的 GameController 框架识别；重新配对蓝牙或重新插入 USB。 |
| GUI 有实时输入，但 ACK 始终未收到 | 检查目标 IP、端口、客体接收器和防火墙；第一次优先改用 Bridge。 |
| Mac 终端只看到 `active` | 点击 GUI 的“发送测试状态”，或打开持续转发开关。 |
| 接收器很快显示 `state timed out` | iPad 停止发送或网络中断；这是正常的防卡键归零保护。 |
| Bridge 可用、NAT 不可用 | 属于当前 NAT 到客体单播可达性问题；记录客体地址和日志，先使用 Bridge。 |
| 游戏没有识别手柄 | 先在 Steam Input 中映射通用手柄；对 Wine 游戏分别检查 DirectInput/XInput 支持。 |

## 6. 当前限制

- 仅支持一个手柄：App 选择第一个带 `extendedGamepad` profile 的控制器。
- 未实现震动、陀螺仪、触摸板、手柄电量和多手柄。
- UDP 协议暂无认证、加密或自动发现；不要暴露到不可信局域网。
- 接收器仍是开发 probe，后续需要包装为客体 root helper，才能不依赖手工打开终端。
- macOS `GameController.framework` 会过滤此虚拟 HID；Safari 和仅使用该
  framework 的原生应用不在当前支持范围内。
